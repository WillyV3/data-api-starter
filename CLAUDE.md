# Rules for this repo

This is a small API on Cloudflare Workers. Keep it boring. The frameworks do the work.

## Stack (do not swap or add to it without asking)

- Hono + `@hono/zod-openapi` for routes. Every route is a `createRoute` with Zod schemas.
- Drizzle ORM on D1 for all database access.
- better-auth + `@better-auth/api-key` for sign-up, sessions and API keys. Never hand-write
  auth, key checking, hashing or rate limiting.
- `public/index.html` is the whole frontend. No build step, no frontend framework.

## Rules

1. No new dependency without asking the user first.
2. Schema changes: edit `src/db/schema.ts`, run `pnpm db:generate`, then `pnpm db:migrate:local`.
   Never write raw SQL against the remote database. Never edit files in `drizzle/` by hand.
   `src/db/auth-schema.ts` is generated by `pnpm auth:generate`; do not edit it.
3. Every endpoint has Zod request and response schemas and at least one test in `test/`.
4. Before saying something works: run `pnpm typecheck` and `pnpm test`, then `pnpm dev` and
   `curl` the endpoint. Report the actual output.
5. All data routes live under `/v1/` so the API-key middleware covers them. Do not add a data
   route outside `/v1/`.
6. Secrets go in `.dev.vars` locally and `wrangler secret put` in production. Never commit them,
   never put them in `wrangler.jsonc`.
7. Do not run `pnpm run deploy` or any `--remote` command unless the user asks for it in that message.
8. APIs in these packages change between major versions. Read the installed types in
   `node_modules` or the current docs before using an API from memory.
